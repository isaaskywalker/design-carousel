# figma-carousel execution 계약

설치된 `figma-carousel`의 SKILL.md를 읽고 지원하는 작업을 확인한다. 아래는 개념적 어댑터 계약이며 존재하는 API 이름이 아니다.

입력: target_file/frame, canvas, safe_area, design-plan.json, 로컬 이미지 자산, editable text, 필수 브랜드 요소, 생성/수정 범위.
출력: 실제 file/frame ID와 링크, 가능하면 렌더·내보내기, 실제 폰트 대체·배치 차이·실패 목록.

디자인 결정은 design-carousel이 한다. 실행기는 요소를 생성·배치·스타일링하고 자산을 넣는다. 불가피한 폰트 대체나 텍스트 크기 조정은 기록하고 위계·줄바꿈을 재검증한다. 계획의 내용이나 레이아웃을 임의로 기존 템플릿에 맞추지 않는다.

기존 figma-carousel이 고정 템플릿만 지원하면 원본 스킬을 자동 수정하지 않는다. 계획을 그대로 구현할 수 있는 Figma 도구로 우회하고 필요한 figma-use/figma-generate-design 등의 실제 지침을 먼저 읽는다. 우회 도구도 없으면 계획과 자산을 납품하고 Figma 미실행을 명시한다.

기본은 새 프레임 생성이다. 기존 프레임 수정 요청에서는 지정 범위만 바꾸고 원본 삭제는 요청 없이 하지 않는다. 이미지 바이트·URL·업로드 방식은 실제 도구 규격을 따른다. 성공 응답으로 연결을 확인하고 렌더를 검사한다. 가짜 Figma 링크나 이미지 경로를 만들지 않는다. 실행 실패 시 성공한 프레임 ID를 유지해 재시도에서 중복 생성하지 않는다.

문화 자산은 asset_id, provenance, 원본 source notes, ready local_path, crop/fit, 얼굴 보호 영역, 레이어 순서를 함께 넘긴다. 실행기는 문화 자산을 임의로 다른 인물이나 AI 사진으로 바꾸지 않는다. 미확보 자산은 플레이스홀더로 표시하고 완료로 보고하지 않는다.
