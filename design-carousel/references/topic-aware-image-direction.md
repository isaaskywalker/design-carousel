# 주제에 맞는 이미지 선택과 처리
## 실제 이미지 탐색
사용자 원본이 있으면 활용하고, 부족하면 실제 가능한 Codex 웹 검색/이미지 검색/브라우저로 Google 등 검색 경로에서 후보를 찾는다. 검색 결과는 발견 경로다. 기사/게시물 원본 페이지로 이동해 사진·대상·장소·날짜·문맥을 확인한다. 검색 스니펫이나 썸네일만 본 상태를 원본 확보라고 말하지 않는다.
기사 사진·Instagram 사진은 실제 원본을 그대로 사용하거나 크롭·누끼 등 필요한 처리만 한다. 공개 출처·사용 가능 여부·원본 경로를 기록하며 웹 이미지 표시/다운로드는 실행 환경 도구의 제약을 따른다. 로그인 차단 시 업로드 자료로 전환한다. 공개 검색 성공과 이미지 파일 확보 성공은 별개 상태다.
건물 외관과 디저트가 동일 장소/지점인지 확인한다. 유명한 다른 카페 사진으로 빈자리를 채우지 않는다. 실제 메뉴·건물·제품을 AI 유사 이미지로 바꾸고 사실처럼 소개하지 않는다.
문화 관련 후보는 visual-culture manifest와 scorer를 사용한다. 일반 장소·음식·제품 후보는 semantic_fit, subject_accuracy, image_quality, composition_fit, source_confidence를 비교한다. 유명세·최신성은 메시지에서 필요할 때만 기준에 추가한다. 문화 scorer를 모든 음식 사진에 강제하지 않는다.

## 이미지 처리 선택
- as_is: 장소 분위기·현장 문맥·완성된 사진 구도가 중요하면 배경 유지.
- crop: 초점과 텍스트 공간을 조정하되 중요한 단서나 의미를 잘라내지 않음.
- cutout: 인물·제품·디저트를 독립 레이어로 쓰는 편이 위계를 개선할 때만. 메뉴/장소의 맥락이 사라지면 원본도 보조로 남김.
- collage: 서로 다른 사진이 한 메시지를 보완할 때. 자산 수는 공간과 설명량으로 결정.
- annotate: 위치·부분·차이를 보여주는 표시. 원본에 없던 사실을 만들어내지 않음.
편집은 사용 가능한 이미지 편집 도구와 해당 스킬을 사용한다. 누끼는 가능하면 transparent background로 내보내고 가장자리·머리카락·제품 형태를 실제 확인한다. 도구가 없으면 treatment 계획으로 남긴다. 원본 파일을 보존하고 derived_path·처리 내용·검증 상태를 기록한다.

## 논쟁과 댓글
사용자가 언급한 인물과 사건의 관계를 최신 공개 근거로 확인한다. 이름이 잘못되었거나 동명이인일 가능성이 있으면 확인 전 사진을 확정하지 않는다. 군 복무/제도 설명은 관련 공식 자료로 사실 확인한다. 이 문서의 예시는 실제 논란이 있었다는 주장이 아니다.
댓글은 사회 반응을 보여주는 편이 메시지에 도움이 될 때만 사용한다. 욕설·혐오·인신공격·사생활 노출이 있는 댓글을 제외하고, 같은 의미를 유지한 읽기 쉬운 원문을 선택한다. 공격적 댓글을 조용히 고쳐 실제 캡처인 것처럼 쓰지 않는다. 생략은 표시하고 의역은 요약 텍스트로 구분한다. 서로 다른 입장을 다루는 콘텐츠는 가능한 범위를 공정하게 선택하며 몇 개의 댓글을 여론 전체로 일반화하지 않는다.

모든 원본 후보에 출처 페이지/원본 미디어 URL, 작성자, 확인 날짜, 사용권 상태/근거, 대상 확인 근거를 남긴다. 미확인은 null/unknown으로 유지하고 공개 이미지라고 사용권을 확정하지 않는다. visual strategy에는 후보 asset_id와 파일 참조를, 별도 source-notes에는 세부 출처를 기록해 Figma 실행 시 연결한다.
