# 장표 간 이미지 중복 방지

사용자가 반복을 명시적으로 요청하지 않는 한 표지를 포함한 캐러셀 전체에서 동일 이미지 원본을 한 장표에만 배정한다. 2장에 사용한 원본을 4장에 다시 배치하지 않는다. 사진·밈·댓글 캡처·제품 화면·생성 이미지·일러스트 모두 해당한다. 크롭·누끼·반전·색보정·리사이즈·일부 확대·콜라주에 포함된 같은 원본은 다른 이미지로 보지 않는다. 같은 인물이나 브랜드의 서로 다른 사진·화면은 실제 장면이 다르면 사용할 수 있다.

## 선정 및 실행

- 후보 확보 시 원본 정체성을 source_asset_id로 관리한다. 파생 자산은 부모 원본 ID를 연결하고, 다운로드한 동일 파일은 해시로 확인한다. 서로 다른 URL·파일명·asset_id만으로 별개라고 판단하지 않는다. CDN 크기 변형·재게시·동일 장면은 출처와 시각 비교로 연결한다.
- 표지·본문을 함께 계획하고 원본별 사용 장표를 usage map에 기록한다. 한 장표에서 여러 역할로 사용했더라도 다른 장표에 재사용하지 않는다. 표지 콜라주가 본문의 이미지를 미리 재사용하지 않도록 별도 원본을 확보한다.
- 기존 manifest 스키마가 추가 필드를 허용하지 않으면 별도 image-usage.json에 source_asset_id, asset_ids, slide_ids, 원본 URL·로컬 경로·파생 관계·검증 상태를 기록한다. Figma에는 ready이면서 사용 장표가 배정된 자산만 전달한다.
- 중복 후보는 내용과 구도가 맞는 다른 실제 원본으로 교체한다. 자산이 부족하면 이미지 수를 줄이거나 타이포·도형으로 구성한다. 아무 관련 없는 사진이나 AI 재현으로 빈자리를 채우지 않는다.
- 로고·워터마크·공통 아이콘처럼 브랜드 식별이나 공통 UI로 명시된 요소는 반복할 수 있다. 이를 핑계로 주요 사진·밈·캡처의 반복을 허용하지 않는다.

## 완료 검사

원본별 slide_ids의 고유 개수가 1을 넘는지 확인한다. 파일 해시 검사는 완전히 같은 파일만 잡으므로 파생 관계와 실제 전체 장표 렌더도 함께 확인한다. 이미지가 중복되면 해당 장표와 원본 ID를 수정 목록에 남기고 교체 후 다시 확인한다. 최신성이 좋아도 중복 gate를 우회할 수 없다. 원본 연결이나 렌더를 확인할 수 없다면 중복 검증 미완료로 보고한다.
